# 安装与本地数据

## 环境

- Node.js 22.14 或更新版本；本轮验证实际使用版本见 `verification.md`。
- pnpm 11.25.0。两个应用各有独立锁文件，分别安装依赖。
- PostgreSQL 17；集成测试会创建/删除专用测试数据库，需要该本机测试角色具备 CREATEDB 权限。
- 微信开发者工具仅用于原生客户端编译和账号内测试。

## 配置

根目录执行 `npm run setup`，生成被忽略的 `apps/web/.env.local`。命令生成独立会话密钥和本地演示密码；已有文件会拒绝覆盖。

默认使用本机 `merchantkit_demo`。如果使用其他端口或本机角色，修改 `.env.local` 中的连接参数。开发脚本不会加载商家原有生产配置。

`db:migrate`、`db:seed` 仅允许 loopback 主机和 `merchantkit_demo` / `merchantkit_test` 数据库。社区首次迁移直接由当前 Prisma 数据模型生成，适用于空库；它不是原商业系统的升级方案。

运行 `db:seed` 前安装依赖、生成 Prisma Client 并迁移空库。初始化仅写入虚构商品、虚构负责人及演示开店设置，包括三个运费档位均为零的本地演示配置；存在用户、商品或订单时拒绝覆盖。实际运营前在后台设置真实运费，不要将演示值直接用于正式商店，也不要改成对现有业务库的自动重置。

## 启动和构建

`npm run dev` 默认仅监听本机 3000 端口。`npm run build` 只构建代码；构建使用临时随机会话密钥，不调用付款或发消息接口。实际 `start` 需要配置自己的独立密钥，生产模式禁止模拟管理员登录。

## 账号和数据

演示账号及商品都是测试数据。演示负责人通过密码登录已有后台；不依赖免密管理员接口。密码仅保存在本机被忽略的配置中，可使用自己的密码重新初始化新的空演示库。

会员与交易完整流程使用 PostgreSQL。`COMMERCE_STORAGE=runtime` 的内存模式仅适合基本渲染和部分单元测试；不要将它宣传成完整、持久化的商城部署。

## 集成测试

单独创建本机 `merchantkit_test`，设置测试进程的 `DATABASE_URL` 后运行 `pnpm --dir apps/web test:integration`。

入口先检查数据库主机和名称；在同一个本机服务中创建随机命名的模板及套件数据库，只写虚构夹具。正常完成或套件失败时会在 `finally` 清理测试数据库；中断进程后应检查遗留的 `merchantkit_test_*` 资源。日志仅保留在应用内被忽略的 `.data/integration`，发布前仍需检查所有待提交文件。

## 正式部署

自行配置 HTTPS、运营者信息、正式隐私及服务协议、备份、访问控制和平台权限。先在自己的沙箱环境核验接口，再启用真实支付、通知和活动。仓库没有自动连接任何既有商家系统的部署流程。
