# 架构

## 应用边界

原生小程序通过 HTTP 调用 `apps/web/app/api/miniprogram`。网站、商家后台和接口通过 `lib/services` 使用同一套数据模型。`lib/commerce` 保存计价、奖励、状态转换、履约资格和输入校验等规则；`lib/providers` 保存第三方接口适配。

服务端核定价格、库存、权限、奖励和支付状态。客户端点击、分享回调、插件完成回调均不能单独证明真实交易、关注、好友关系或积分到账。

## 数据与交易

Prisma schema 描述用户、会员、商品、购物袋、订单、支付、售后、退款、积分、优惠券、物流和自提等关联。社区版空库迁移是新发行基线。生产商家的历史数据和迁移运行记录不随代码发布。

关键写入使用身份校验、状态规则和幂等请求标识。自提流程区分资格判断、创建取货码、备货、核销与同步结果。退款处理区分申请、真实渠道退款、回调/查单和订单最终展示。

## 平台适配

微信登录、支付、退款、学生验证、订阅、物流，以及企微等接入需要部署者拥有相应账号和权限。适配代码并不转移平台授权。默认示例不包含可调用某家真实商户的身份或密钥。

## 内容与素材

商业品牌故事、政策及照片已经替换为社区说明和原创占位图。组件仍可渲染运营者自己配置的内容。占位图可以通过 `npm run assets:generate` 重建，生成器使用代码中的原创几何图形，不读取原商业照片。
